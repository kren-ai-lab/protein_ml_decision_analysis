# Training process workflow

This workflow trains machine learning models using the valid train/validation/test splits generated by the `split_dataset` workflow. It is the final computational stage of the pipeline.

```text
split_process/<dataset>/
   ↓
training_process
   ↓
training_process/<dataset>/
```

The workflow reads each `split_summary.csv` file and only trains on split runs marked as:

```text
status == kept
```

Invalid splits are skipped automatically.

---

## 1. Objective

The `training_process` workflow runs model training across the valid experimental scenarios generated by the split workflow.

It can:

1. discover valid splits automatically from `split_process/<dataset>/`;
2. filter splits by scenario, strategy, seed, or reduction level;
3. train one or more machine learning algorithms;
4. run one or more feature scaling strategies;
5. save training outputs in a structured folder under `training_process/<dataset>/`.

This workflow does not generate splits. It only uses the valid partitions created by `split_dataset`.

---

## 2. Workflow location

This workflow should be located at:

```text
pipelines/training_process/
├── Snakefile
└── config/
    └── config.yaml
```

Run all commands from inside this folder unless stated otherwise.

---

## 3. Required inputs

This workflow assumes that the `split_dataset` workflow has already been executed.

Expected input structure:

```text
split_process/
└── <dataset>/
    ├── <scenario>/
    │   └── <strategy>/
    │       └── seed_<seed>/
    │           ├── split_summary.csv
    │           ├── no_threshold/
    │           ├── p90_0/
    │           └── threshold_0.7/
    └── split_analysis/
```

Each valid split folder should contain:

```text
fold_00/
├── train.csv
├── val.csv
└── test.csv
```

The `split_summary.csv` file is used to decide which reduction levels are valid for training.

---

## 4. How to run

From the workflow directory:

```bash
cd pipelines/training_process

python -m snakemake \
  --cores 8 \
  --rerun-incomplete \
  --latency-wait 60 \
  -p
```

To preview jobs without executing them:

```bash
python -m snakemake -n -p
```

## 5. Main configuration blocks

### 5.1 `global`

```yaml
global:
  output_root: "../.."

  seeds_file: "../../general_configs/random_seeds_30.csv"
```

- `output_root` : Project root used to infer input and output folders 
- `seeds_file` : Optional seed list used when `selection.seeds` is not `"auto"` 

The value `../..` assumes that the workflow is executed from:

```text
pipelines/training_process/
```

From that location, `../..` points to the project root.

---

### 5.2 `dataset`

```yaml
dataset:
  name: "test"
  label_col: "label"
```

- `name` : Dataset name used to find `split_process/<dataset>/` 
- `label_col` : Classification label column used during training 

Changing `dataset.name` changes the expected input and output folders:

```text
split_process/<dataset.name>/
training_process/<dataset.name>/
```

---

### 5.3 `input`

```yaml
input:
  split_root: null
```

If `split_root: null`, the workflow reads splits from:

```text
<output_root>/split_process/<dataset.name>
```

You can also provide a custom split folder:

```yaml
input:
  split_root: "/path/to/split_process/my_dataset"
```

---

### 5.4 `output`

```yaml
output:
  root: null
  include_dataset_folder: true
```

If `root: null`, outputs are written to:

```text
<output_root>/training_process/<dataset.name>
```

If `include_dataset_folder: false`, outputs are written directly under:

```text
<output_root>/training_process/
```

## 6. Selecting what to train

The `selection` block controls which valid split runs are used for training.

```yaml
selection:
  scenarios: "auto"
  strategies: "auto"
  seeds: "auto"
  reduction_levels: "auto"
  required_status: "kept"
```

- `scenarios` : Which scenario folders to train 
- `strategies` : Which split strategies to train 
- `seeds` : Which seeds to train 
- `reduction_levels` : Which reduction levels to train 
- `required_status` : Split status required for training 

When set to `"auto"`, the workflow discovers all available valid values.

---

### 6.1 Examples

Train everything valid:

```yaml
selection:
  scenarios: "auto"
  strategies: "auto"
  seeds: "auto"
  reduction_levels: "auto"
  required_status: "kept"
```

Train only one scenario:

```yaml
selection:
  scenarios:
    - "esm2_t6_8M_UR50D_no_reduced"
  strategies: "auto"
  seeds: "auto"
  reduction_levels: "auto"
  required_status: "kept"
```

Train only selected split strategies:

```yaml
selection:
  scenarios: "auto"
  strategies:
    - "random_kfold"
    - "stratified_kfold"
  seeds: "auto"
  reduction_levels: "auto"
  required_status: "kept"
```

Train only specific reduction levels:

```yaml
selection:
  scenarios: "auto"
  strategies: "auto"
  seeds: "auto"
  reduction_levels:
    - "no_threshold"
    - "p90_0"
    - "p95_0"
    - "threshold_0.7"
  required_status: "kept"
```

## 7. Training configuration

```yaml
training:
  enabled: true

  script: "../../notebooks_and_scripts/scripts_for_pipelines/training_model_external_cv.py"
  config: "../../general_configs/config_hyperparameters_algorithm.json"

  algorithms:
    - "LogisticRegression"

  scalers:
    - "none"

  feature_prefix: "p_"
  timestamp: false
  extra_args: ""
```

 `enabled` : Enables or disables training 
 `script` : Training script used by the workflow 
 `config` : JSON file with model hyperparameters 
 `algorithms` : List of models to train 
 `scalers` : List of scaling strategies 
 `feature_prefix` : Prefix used to identify feature columns 
 `timestamp` : Whether to add timestamps to outputs 
 `extra_args` : Extra command-line arguments passed to the training script 

---

### 8.1 Algorithms

The algorithm names must exist in:

```text
general_configs/config_hyperparameters_algorithm.json
```

Example:

```yaml
training:
  algorithms:
    - "LogisticRegression"
    - "RandomForestClassifier"
    - "ExtraTreesClassifier"
```

Common options include:

```yaml
# - "LogisticRegression"
# - "RandomForestClassifier"
# - "ExtraTreesClassifier"
# - "SVC"
# - "KNeighborsClassifier"
# - "DecisionTreeClassifier"
# - "GaussianNB"
# - "XGBClassifier"
```

---

### 8.2 Scalers

Example:

```yaml
training:
  scalers:
    - "none"
    - "standard"
```

Use `none` when the features are already suitable for the selected model or when you want a direct baseline.

## 9. Output structure

A typical output folder looks like this:

```text
training_process/
└── <dataset>/
    ├── <scenario>/
    │   └── <strategy>/
    │       └── seed_<seed>/
    │           └── <reduction_level>/
    │               └── <algorithm>/
    │                   ├── exploration_by_fold_<algorithm>_scaler_<scaler>.csv
    │                   ├── status_<algorithm>_scaler_<scaler>.log
    │                   └── training_done_scaler_<scaler>.txt
```

Example:

```text
training_process/
└── test/
    └── esm2_t6_8M_UR50D_no_reduced/
        └── random_kfold/
            └── seed_4617/
                └── no_threshold/
                    └── LogisticRegression/
                        ├── exploration_by_fold_LogisticRegression_scaler_none.csv
                        ├── status_LogisticRegression_scaler_none.log
                        └── training_done_scaler_none.txt
```

## 11. Using a new dataset

1. Run the previous workflows:

```text
numerical_representations
reduce_dataset
split_dataset
```

2. Update the dataset name:

```yaml
dataset:
  name: "my_dataset"
  label_col: "label"
```

3. Check that the split folder exists:

```text
split_process/my_dataset/
```

4. Optionally filter what to train:

```yaml
selection:
  scenarios: "auto"
  strategies: "auto"
  seeds: "auto"
  reduction_levels: "auto"
  required_status: "kept"
```

5. Run the workflow:

```bash
cd pipelines/training_process

python -m snakemake \
  --cores 8 \
  --rerun-incomplete \
  --latency-wait 60 \
  -p
```

6. Check outputs under:

```text
training_process/my_dataset/
```
